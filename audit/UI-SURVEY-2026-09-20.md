# UI survey — 2026-09-20 (goal 20260920183415-d38vs8)

Full-surface survey of GLLA glance UI. Method: headless renders of every
card state at width 120/190 plus code reading of the status and recap
paths. Before-renders: `audit/ui-survey-2026-09-20/before-widget-cards.txt`.
Pi core truncates widget tails at ~10 rows, so row order IS priority order.

## Ranked findings

1. **Decision cards bury the action under up to 7 options (16 rows).**
   Paused-decision with 7 options renders lifecycle + banner + reason, then
   all options, then saved/action, then history. Pi core cuts at ~row 10,
   so the action (`Choose one, then /list resume`) and the late options
   vanish. Fix: render the action/next row BEFORE the options; options
   already live in full in the `ask_user_question` dialog. Status: TODO.
2. **Status line truncates the resume command first.** `next: /list resume`
   rides at the segment tail, so narrow terminals (`width 60/100`) cut
   exactly the actionable part; version tail and worker summary go with it.
   Fix: lead state + next, trail version/workers. Status: TODO.
3. **Plaque body doubling on active cards.** `1. Durable fix — Implement
   Implement Keep sticky/...`: the renderer prefixes a verb the stored
   body already starts with. Fix: dedupe the prefix when the body carries
   its own verb. Status: TODO.
4. **Recap content skew (behavioral, not rendering).** The recap renderer
   already budgets, clips machine tokens, and filters stale Next lines;
   remaining noise comes from agents writing verification-heavy Outcome
   text. No renderer change proposed; covered by drafting guidance.
5. **Settings menus surveyed, no finding.** The `/glla` settings table
   renders in a menu dialog outside the widget row budget.
